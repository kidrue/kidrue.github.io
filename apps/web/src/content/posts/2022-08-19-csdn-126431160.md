1.  首先克隆一份代码下来（默认main分支）。  
    `git clone https://github.com/kidrue/gittest.git`
    
2.  创建并切换分支开始工作（分支相当于一个独立的版本，以创建分支时的为版本保存新分支）。  
    `git checkout -b dev` 或 `git switch -c dev` 创建并切换到dev分支  
    `git push --set-upstream origin dev` 推送代码并设置本地当前分支的上游分支（也就是远程仓库分支），如远程仓库没有该分支，则会创建dev分支  
    上述命令类比于以下两行  
    `git branch dev`  
    `git switch/checkout dev`
    

-   另外：切换分支前注意保存，否则会影响切出去的分支依然会存在修改文件，有以下三种方式： \*
    1.  `git push` 推送远程仓库
    2.  `git commit -m '描述'` 提交到缓存区
    3.  `git add .` 提交到暂存区 ，  
        `git stash -m '描述'` 备份暂存区内容起来，  
        `git stash pop (保存索引)` 保存到当前工作区并删除备份

3.  工作完成后首先拉取远程仓库代码，然后进行推送本地代码至远程仓库。  
    `git pull //冲突应当在此处解决` 拉取代码  
    `git add .` 将修改代码提交缓存区，可通过`git status`查看  
    `git commit -m '初次提交工作代码'` 代码并附带描述提交至本地仓库  
    `git push` 代码推送至远程仓库
    
4.  切换主分支，并合并代码。  
    `git switch/checkout main` 切换至main分支  
    `git merge dev` 合并dev分支  
    `git push` 推送合并后代码至远程仓库  
    `git branch -d dev` 删除开发分支
    

* * *

`git stash -m '暂存描述' //保存当前暂存区内容` 操作暂存区，便于切换分支提交代码时，而不被暂存区代码影响  
`git stash pop // 删除暂存区数据并保存到当前工作区`  
`git checkout -b test（本地分支） origin/test（远程分支）` //创建分支并链接远程仓库分支，会切换工作区所有文件

-   分支相当于版本

* * *

-   至此工作代码提交完成 (新版本发布了switch，checkout由于有两种作用切换分支和检查文件，容易混淆，git更推荐使用switch切换分支等操作)
    
-   回滚版本  
    `git reset HEAD(commit提交是分配的序列号)`  
    `git reset --hard HEAD(commit提交是分配的序列号)` （ --hard为硬提交）  
    `git reset --soft HEAD(commit提交是分配的序列号)` （ --soft为软提交）  
    `git push -f origin master` （将回退版本信息提交给远程仓库，并抛弃head后的所有commit）
